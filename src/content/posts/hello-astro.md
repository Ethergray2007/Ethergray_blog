# 开始搭建 EtherGray Blog

最近开始搭建自己的个人博客，于是选择了 Astro 作为基础框架。

之前接触过一些前端技术，但一直没有认真做过一个完整的网站。相比从零开始写一个博客，使用成熟的模板可以把更多精力放在内容和后续功能上。

## 为什么选择 Astro

Astro 的一个特点是非常适合内容型网站。

博客的大部分内容其实都是：

- Markdown 文章
- 图片
- 页面
- 少量交互

并不需要每一个页面都运行大量 JavaScript。

Astro 可以把页面尽可能多地作为静态 HTML 输出，这对于博客这种网站非常合适。

## 这个博客是怎么跑起来的

本地开发只需要一条命令：

```bash
npm run dev
```

它会在 `http://localhost:4321` 起一个开发服务器。改任何文件，浏览器都会立刻刷新，不用手动重启。

写完之后构建成静态文件：

```bash
npm run build
```

构建产物在 `dist/` 目录里，全都是普通的 HTML、CSS、JS。也就是说，它不依赖任何后端服务，扔到任意一个静态托管上就能跑。这个博客目前部署在 Netlify 上。

## Astro 的组件长什么样

一个 `.astro` 文件分成两半：上面是**服务端代码**（用 `---` 包起来），下面是**模板**。

```astro
---
// 这一部分在构建时执行，浏览器看不到
import config from "@/config";

const title = "我的博客";
const posts = await getCollection("posts");
---

<!-- 这一部分是模板，会被渲染成 HTML -->
<h1>{title}</h1>

<ul>
  {posts.map(post => <li>{post.data.title}</li>)}
</ul>
```

这种设计的好处是：**能写 JavaScript 的地方就是构建时**，所以取数据、算格式这些事情都不需要发到浏览器里。

## 为什么使用 AstroPaper

这次使用的是 AstroPaper。

它已经把博客最基础的功能准备好了，例如：

- 文章列表
- 标签
- 归档
- 搜索
- 深色 / 浅色模式
- RSS
- Markdown / MDX
- 自动生成页面

这样不用重新实现一个博客系统，可以直接在现有结构上修改。

## 接下来准备做什么

目前主要还是把模板改造成自己的博客。

准备先完成：

1. 中文界面
2. 修改网站信息
3. 清理模板自带的示例文章
4. 修改首页
5. 添加自己的文章
6. 部署到 Netlify

博客并不准备一次性把所有东西都设计好。

先把基础版本跑起来，然后在实际使用过程中不断修改。

毕竟真正使用之后，才知道哪些功能是需要的。

这也是建立这个博客的一个目的：

**把学习过程本身记录下来。**

## 后续进展（2026-09-30 补记）

上面那六件事后来都做完了。除此之外还做了不少原本没计划的事，
这里补记一下，免得这篇"开始"的文章停在一个过时的位置：

**界面与内容**

- 中文化、清理模板示例内容、改首页
- 补了文章目录（TOC）和代码块一键复制
- 加了 `/now` 页面记录近况
- 标签页显示每篇文章数量，归档页按年份汇总常用标签

**功能**

- 接上了 PostgreSQL 数据库（Neon）
- 用 Elysia 写了一套接口，用 Drizzle 做数据访问
- 做了一个**只给自己用的在线写作后台**：登录后可以在浏览器里写文章、
  改、删除、切换草稿与发布，不用再改代码
- 登录用 GitHub 账号（Better Auth），数据库里不存任何密码

**工程上的整理**

- 删掉了模板自带的一堆用不上的东西（Docker 配置、给上游项目用的
  贡献指南、示例截图等）
- 加了 73 项自动测试，覆盖数据层、接口和登录权限
- 配了 GitHub Actions，每次推送自动跑格式检查、类型检查、构建和测试

现在回头看，"先跑起来再慢慢改"这个判断是对的。
如果一开始就想着把所有东西设计好，大概到现在还没上线。

真正用起来之后才发现的问题，比事先能想到的多得多 ——
比如"未登录时接口该返回 401 还是 422"这种细节，
是写测试的时候才意识到的。
